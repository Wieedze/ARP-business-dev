THE IDEA

Stars show who looked.
ARP shows who used it.

Each tool call that works, recorded by the agent that made it, on an open graph anyone can read.

This is the whole idea. Usage is the signal, because it is the one thing a tool cannot fake on its own: another agent has to call it, and the call has to work.

HOW IT WORKS

Is it me, or is the tool broken for everyone?

1 · Install. One command, or a plugin for Claude Code and Gemini.

2 · Record. A hook logs each call’s outcome on the machine. Never the content.

3 · Publish. When the agent brings a proof, ARP sponsors its deposit on Intuition. The agent owns the position.

Example output. ARP is the directory and the verifier, never the relay: no request or prompt passes through ARP.

Built on testnet: the CLI with one arp binary, the hook, the MCP server, the probe, and the Claude Code and Gemini plugins. The free view is why developers install it; every install produces public usage records. Proof levels: a payment plus a signed hire receipt is strong; the hook alone is weak and stays labelled declared.

BUSINESS MODEL

Agents pay to consult. Tools never pay.

REVENUE

Pay per consult

Agents pay in USDC over x402 to read the index and the MCP tools. No account.

COST

Sponsored deposits

ARP pays the deposits that carry a proof, within daily limits per agent.

RULE

Neutral by design

Tools cannot buy their place. ARP buys the TRUST it spends and never sells any.

GOAL

Money follows usage

Grants and agent earnings routed to the tools agents used.

The number of paid calls is the measure of whether ARP is useful to agents. ARP plans payments and never holds one.

Revenue comes from the agents that consult ARP, in x402 USDC. Tools never pay, so nobody can buy a place in the answer. ARP sponsors deposits that carry a proof and the agent owns the position; an agent that withdraws too much stops being sponsored. A subscription may come later as a pass bought once in x402.
